# 公共存储规范与记忆保存恢复的范围

本次以统一存储失败处理为首要目标，同时减少重复文件读写代码并支持自动恢复。文件与数据库统一错误分类，数据库保留现有 Repository；第一版跨服务重启恢复只覆盖记忆保存任务，并提供结构化日志及可查询的任务记录，聊天界面不展示记忆状态。

模型抽取并通过校验后才登记可恢复的保存任务；跨重启恢复使用已经确定的变更内容，只继续保存，不重新调用模型抽取。因此，抽取尚未完成或任务尚未确认登记时的中断不在恢复保证内。自动恢复窗口默认最多 24 小时，逐渐降低尝试频率；超过窗口则标记失败，保留记录供手动重试。

这个范围处理已登记记忆保存任务在重启时丢失的问题，同时保留主执行的关键持久化边界。Checkpoint、工具结果和附件暂不进入跨重启恢复队列；主执行与记忆任务的结果分别判断，关键状态未确认保存时不得报告主执行成功。

删除来源对话时取消未完成的记忆保存任务，已经保存的用户记忆继续保留。已经开始的同步文件提交须完成并核实结果，取消停止后续保存项，不自动回滚。通过后台管理命令查询、重试和取消任务，第一版不新增任务管理 API。一次任务允许多条变更部分成功，分别记录每条变更的完成情况，恢复只处理未完成部分，不自动回滚已经保存的条目。

待恢复任务不阻塞同一用户后续任务。旧保存项恢复时若发现目标记忆已经变化，标记冲突并等待人工判断，禁止自动覆盖新内容。损坏的记忆正文保留并报告错误，跳过该条，其他正常记忆继续使用；损坏索引仍可依据正常正文重建。

人工处理冲突仅支持查看并保留当前记忆、取消旧保存项，第一版不提供旧内容覆盖命令。普通存储失败超过恢复窗口后，手动重试会开启新的 24 小时窗口，同时保留此前的尝试和失败历史；该操作不能绕过冲突检查。可恢复任务和每条保存项的记录使用现有 SQLite 的新增任务表，记忆正文继续保存在文件中。

自动恢复窗口从任务确认登记成功时开始计时，包含排队时间；服务重启不重置窗口，手动重试从确认重启任务时重新计时。任务成功或取消后清除任务记录中复制的记忆内容，保留状态、错误和尝试历史 30 天；未处理的失败或冲突任务保留待保存内容，供人工处理。
