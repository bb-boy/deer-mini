# SSE 实时发送与辅助日志实施计划

**目标**：文字发送不等待 SQLite 日志提交；日志有限重试后失败可告警，关键状态保存失败仍使 Run 失败。

**已确认的设计**：复用 `RunEvent` 和 `StreamEvent`，不增加 `LiveEvent`。DeerFlow 的参考是 `runtime/runs/worker.py` 的直接发布、`runtime/journal.py` 的完整消息缓冲与批量保存。Mini 保留 Agent / 工具闭环和 SQLite Checkpoint，采用单进程内存流。

**实施与验证**：当前任务内直接实施；使用仓库外的 Git 工作区和测试数据库验证，完成后将差异应用回原项目，保留供用户检查的未提交改动。

- [x] `events_repository.py`：新增同一个 Run 的有序批量事务；以事件 UUID 保证重试幂等；事务提交成功后才返回 sequence；SQLite 锁等待有限。
- [x] `event_recorder.py`：立即包装并发布事件；文字片段不入日志；其他事件进入有数量、字节上限的队列，单个后台任务用工作线程写库，批量、延时刷新、退避重试、有限收尾，警告走应用日志。
- [x] `agent_runtime.py`、`context.py`、`lead_agent.py`、`run_coordinator.py`：关键数据库操作在工作线程中执行并等待结果；完整模型消息、工具结果继续保存 Checkpoint。每轮文字与完整消息共享 message_id。终态在关键状态确认后发送；错误、取消、超时都收尾日志及 Stream，保留原始异常。
- [x] `stream_bridge.py`、`routes.py`：实时游标独立于数据库 sequence；优先按内存游标回放；有界缓存缺口或重启后发送状态快照并恢复实际日志；不依赖日志存在来判断终态。
- [x] `run-stream.ts`、`useAgentRun.ts`：处理快照与实时游标，按消息身份避免恢复后的重复文字，忽略旧连接的迟到回调；前端按动画帧平滑追赶文字，完成时立即显示已收到的内容。
- [x] 回归检查：慢写库仍及时收流；临时失败重试按序且不重复；永久日志失败不改变成功；Checkpoint 或 Run 状态失败不报成功；取消等待在途写入；重连不重复；失去流后从状态恢复；流结束不冒充成功；文本平滑、终态追赶和切换对话。
- [x] 用本地生成的文字片段、真实 HTTP SSE 和临时 SQLite 做可重复延迟实验；运行测试及前端构建；检查 Git 差异。
- [x] 将验证后的差异应用回原项目并重启空闲后端；前端服务恢复，页面、接口转发与历史 SSE 恢复检查通过。改动保留为未提交状态。

**最终实现细节**：Run/Thread 进入终态之前先归还 Sandbox，避免下一轮被上一轮的日志收尾拦住。最初的归属查询也纳入取消收尾；未通过归属验证的请求不能修改或关闭其他 Run。前端快照与新 Run 会淘汰旧消息刷新，但保留文件和运行记录刷新。缓存缺口恢复同时重放实际存在的工具日志。

**验证结果（2026-09-13）**：隔离工作区后端 `pytest -q --ignore=tests/app/model/test_factory.py`：126 passed、9 skipped；前端 `pnpm test`：30 passed；`pnpm build` 与 `git diff --check` 通过。两项真实模型工厂测试依赖模型服务配置，本次未调用外部模型。后端旧测试需要预先建表，仅在隔离工作区初始化其测试数据库。

**HTTP 延迟实验**：同一主机、本地生成 24 个片段，目标间隔 20ms，每次辅助日志写入额外等待 150ms。片段从生成到 HTTP 客户端收到的延迟中位数从 321.78ms 降为 0.31ms；收到片段的间隔中位数从 342.11ms 降为 20.49ms。强制全部辅助日志失败时，24 个片段全部收到，完整回答保存在 Checkpoint，Run 为 success。此实验不含真实模型生成耗时和浏览器绘制耗时。

**已知基线**：前端 16 项通过。后端 90 项通过、9 项跳过、5 项失败（3 项测试依赖默认库预先建表，2 项依赖真实模型环境变量）。验证使用隔离库，不读取或改写实际聊天数据库。

**边界**：内存中尚未落库的实时尾部和辅助日志不能保证跨进程崩溃恢复；关键消息以 Checkpoint 为准。操作系统级卡死的写盘不能由 Python 强行终止，有限等待超时后停止追加重试并继续观察已开始的写入。
