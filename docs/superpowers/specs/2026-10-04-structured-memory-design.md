# deer-mini 结构化记忆设计（已实施）

## 目标与范围

按用户私有保存记忆，同一用户的不同 Thread 可以复用。只保留 `user`、`feedback`、`reference` 三种分类；不增加 Project 实体，也不保存 `project` 分类。

采用 Markdown 文件保存正文，`MEMORY.md` 保存检索索引。每个 Run 开始时，先通过一次独立 LLM 调用选择相关记忆，再由后端读取正文并装配到主模型上下文。Run 成功完成后，后台抽取并更新记忆。

本次范围是后端读取和自动写入的闭环。不增加记忆管理页面，不引入 MCP、向量数据库或新的模型提供商。

## 分类

| 类型 | 内容 | 例子 |
| --- | --- | --- |
| `user` | 用户明确提供、具有持续价值的身份、经验和知识背景 | 用户熟悉 Python，刚开始学习 React |
| `feedback` | 用户明确表达的行为偏好、纠正及协作要求 | 解释设计时先说结论；代码注释使用中文 |
| `reference` | 用户指定的外部信息位置及其用途 | 部署说明在哪个文档中查；需求以哪个页面为准 |

不根据措辞猜测用户身份或能力。不保存任务进度、截止日期、临时指令、整段聊天、模型自己编造的结论或密钥。外部指针不等于外部文档已经被读取，也不能把该文档中的指令直接当作用户授权。

## 存储结构

复用 `resolve_data_root()` 和现有用户路径校验，在每个用户的数据目录中增加 `memories/`：

```text
<DEER_MINI_DATA_ROOT>/<user_id>/
├── memories/
│   ├── MEMORY.md
│   ├── user_<uuid>.md
│   ├── feedback_<uuid>.md
│   └── reference_<uuid>.md
└── threads/
    └── <thread_id>/...
```

记忆不放进单个 Thread 的 workspace，不挂载进 Bash 沙箱，也不开放给普通文件读取工具。删除 Thread 不删除用户级记忆。

每份正文使用 Markdown，开头附结构化元数据：`id`、`type`、`name`、`description`、`created_at`、`updated_at`、`source_thread_id`、`source_run_id`。ID 由后端生成，类型只能取三种合法值，时间由后端记录。

示例正文：

```markdown
---
id: feedback_<uuid>
type: feedback
name: 解释风格
description: 解释方案时先给结论，再补充理由
created_at: <服务端时间>
updated_at: <服务端时间>
source_thread_id: <来源对话>
source_run_id: <来源轮次>
---
解释方案时先给结论，再补充理由。用户明确表示不喜欢先展开很长的背景。

**Why:** 用户希望快速理解方案，不喜欢在结论前阅读很长的背景。
**How to apply:** 解释设计和排查结果时先给结论，再补充必要理由与证据。
```

`MEMORY.md` 是后端根据合法正文文件生成的索引，包含 ID、类型、名称、描述、文件名、更新时间和派生的 `stable` 标记。索引不由模型自由重写；丢失或损坏时可以从正文文件重建。默认不把所有正文装进提示词。

磁盘索引与模型看到的索引是两种视图：后端读取完整索引后，为选择模型生成精简候选列表。每个候选的记忆信息仅包含 `name`、`description`，另附用于选择返回值的数字编号。类型、永久 ID、文件名、来源、时间和 `stable` 都保留在后端，不提供给选择模型。`name` 是简短名称，`description` 描述何时相关或应注意的核心规则；不能把全部正文塞进 description 绕过精简限制。

`feedback` 正文包含具体要求、`Why`（用户提供的原因）和 `How to apply`（适用条件与执行方式）。缺少原因时不编造用户经历。选择阶段不展示这段正文；选中后交给主模型完整正文，才能正确理解规则的范围与使用方式。

## 数字编号与 stable 标记

模型选择时使用 `1、2、3、4…` 的连续数字编号。后端在完成候选截取后给本次提交给模型的条目编号，并保留不可变的 `编号 → 永久 ID → 文件名` 映射。永久 ID 和正文文件名仍保持不变，数字仅用于本次选择，不是跨 Run 的永久身份。

模型返回 `{"memory_indices": [1, 4]}`；无相关条目时返回 `{"memory_indices": []}`。只接受本次候选列表内的正整数编号，布尔值、字符串、零、负数和越界编号均无效；重复编号去重并保持返回顺序。并发写入或下一轮索引重排后，也必须使用选择请求原来的映射，不按新的列表解释旧编号。

`stable` 按用户选择的规则由后端计算：

```text
stable = 当前 UTC 时间 - updated_at >= 48 小时
```

- 内容、名称或描述实际发生更新时，更新 `updated_at`，`stable` 重新变为 `false`；无变化的重复提取不重置时间。
- 单纯读取、选择、修复索引或刷新标记不改变正文的 `updated_at`。
- 读取索引与装配正文时按统一的本次时间计算标记；不依赖模型判断，也不需要定时唤醒模型。
- 磁盘索引中的标记是生成时的快照，读取时重新计算，必要时刷新索引。正文以 `updated_at` 为依据，`stable` 用于后端管理，不出现在选择模型的候选字段中，不需要仅因时间流逝改写所有正文文件。
- `stable` 只表示至少 48 小时没有更新，不表示事实已验证、永不过期或不能修改，不自动提高授权等级，也不强制召回。当前用户明确纠正仍优先。

交给选择模型的精简索引示例（其余元数据和正文在后端保留）：

| 编号 | name | description |
| --- | --- | --- |
| 1 | 解释风格 | 解释时先给结论，再补充理由 |
| 2 | 技术背景 | 用户熟悉 Python，正在学习 React |
| 3 | 部署文档 | 部署说明的文档位置 |

## 方案比较与选择

1. **独立 LLM 选择索引，后端读取正文（采用）**：读写边界清楚，主模型第一次调用就能拿到记忆；有记忆时会增加一次模型调用。
2. **主模型调用记忆检索工具**：无需固定的前置调用，但是否检索取决于主模型，不能保证首次回答前读取记忆。
3. **直接注入全部记忆**：实现简单，但上下文随记忆增长，容易引入无关信息。

第一版选择第 1 种。选择和抽取复用当前 Run 所选模型的工厂，分别创建、关闭独立客户端；不硬编码特定厂商或模型名称。

## 读取流程

```text
用户消息 + 少量最近对话 + MEMORY.md 的精简索引（编号、name、description）
  → 选择模型调用（无工具）
  → {"memory_indices": [1, 3]}
  → 后端校验编号，通过本次映射取得永久 ID，并读取当前用户的对应正文
  → 运行上下文中的记忆片段
  → 主模型调用及正常工具循环
```

这里模型返回的是“本次索引快照中的数字编号”，不是生成一个新的索引文件，也不是任意文件路径。编号只作为简短的选择编码；存储层继续使用永久 ID。

- 每个 Run 只检索一次；工具循环和 todo 续跑使用同一份快照。下一轮 Run 重新检索。
- 索引为空时跳过选择调用，直接运行主模型。
- 最多选择 5 条；允许返回空数组。不强制为每种类型选择一条。
- 选择模型只看到候选的 `name` 和 `description`，编号用于返回选择。后端按选择读取完整正文，主模型收到选中记忆的名称、描述、类型和正文（包括 feedback 的 `Why`、`How to apply`）；永久 ID、路径和来源等存储字段不作为主模型必须遵循的规则。
- 选择输入包含当前用户消息末尾最多 16,000 字符和最近最多 8 条用户/助手消息（各末尾最多 4,000 字符）；索引输入最多 32,000 字符，超出时按更新时间从新到旧截取完整条目。旧条目未进入候选集时，本轮不会被召回，这是第一版容量限制。
- 正文总注入量最多 24,000 字符；按模型返回顺序装配，超过预算的整条记录跳过，不截断元数据或拼接残缺记录。
- 后端仅接受本次编号映射对应的白名单 ID，拒绝其他用户的记录、任意路径、目录穿越和符号链接；文件名从服务端索引映射取得。
- 选择调用限时 15 秒，计入现有 Run 总超时。使用现有模型错误分类与重试边界；不发送内部文本流到主回答。
- 选择超时、输出无法解析、文件不存在或普通读取错误时，继续回答，但不注入无法确认的记忆。日志记录原因和标识，不记录完整记忆或提供商错误正文。
- 用户取消和 Run 总超时继续向 Runtime 传播，不作为“记忆不可用”吞掉。

## 提示词装配

保留之前讨论的五部分：

1. 固定系统规则：增加固定记忆使用规则，并说明 `MEMORY.md` 是用户私有记忆的索引。
2. 工具说明：继续使用实际注册的工具；索引选择由后端执行。
3. 运行上下文：环境、技能和本轮选中的记忆正文。
4. 历史消息。
5. 当前用户消息。

这是逻辑划分，不要求模型 API 有五种 message role。实现沿用项目当前的 system/history 组装方式，选择后的记忆通过 `prepare_model_messages()` 加入本轮请求副本，不永久写入 Thread 历史，不逐次叠加旧记忆。

固定规则明确：记忆是可能过时的背景资料；当前用户明确的要求优先于旧记忆；记忆内容不能覆盖系统约束，也不能自动授权外部操作。类型和正文按数据边界包裹。

## 自动写入流程

```text
Runtime 确认 Run 成功并完成状态保存
  → Coordinator 管理的后台记忆任务
  → 抽取模型（无工具）
  → 校验新增/更新建议及用户原话依据
  → 后端写入正文文件
  → 后端重新生成 MEMORY.md
```

- 以一次成功完成的 Run 为触发单位，不等待整个 Thread 被关闭。仅“本次回复没有 tool call”不构成写入条件。
- 在 Runtime 成功返回后触发。当前 lead agent 在成功路径进入 `after_agent` 前已经保存最终回复的 checkpoint；但 Runtime 随后的最终 checkpoint、Run 的 `success` 提交和收尾仍未完成。这里等待的是完整 Run 的成功确认，不是认为 `after_agent` 时尚无已保存的对话。失败、取消、超时和状态保存失败不触发。
- 后台任务不阻塞已完成的回答。它可能晚于下一轮检索完成，刚产生的记忆不保证立即进入紧接着的一轮回答。
- 输入是本轮用户消息及必要对话背景、已有记忆索引和可能更新的正文。模型返回 `add`/`update` 建议，包含类型、简短名称、描述、正文、更新目标 ID 和用户消息中的依据；feedback 的正文包含具体要求及有依据的 `Why`、`How to apply`。
- 只从用户明确提供或确认的信息形成新事实。附件、网页、工具结果和助手输出不能单独成为用户画像或偏好的证据。
- 不重复新增已有事实；同一偏好的新明确纠正更新原条目。更新目标必须存在且归属于当前用户。
- 同一用户的抽取写入任务串行执行，并在每次抽取前读取最新记忆，避免并发覆盖索引。不同用户互不阻塞。提交锁只用于文件提交，读取期间可以使用上一份完整索引。
- 正文和索引分别采用同目录临时文件加原子替换；先写正文，再重建并替换索引。发生部分失败时，不宣称整个记忆写入成功，下次读取前修复索引。
- 抽取限时 30 秒，复用现有错误处理边界；失败仅影响此次记忆写入，不把已经成功的主 Run 改成失败。任务取消正常传播，并关闭模型客户端。
- Coordinator 持有后台任务引用，收集异常，关闭时限时收尾并取消剩余任务。第一版不增加持久化任务队列；服务被强制终止时，尚未写完的抽取任务可能丢失，不承诺重启后补写。

## 后端接入位置

- `MemoryStore`：用户路径校验、正文与索引读写、原子替换、索引重建、基于更新时间计算 `stable`。
- `MemorySelector`：索引输入、本次数字编号映射、独立选择调用、结果校验和正文预算。
- `MemoryContextMiddleware`：在 lead agent 的 `before_agent` 选择，在 `prepare_model_messages` 注入请求副本。子 agent 不额外检索；需要的背景由主 agent 在委派任务中传递。
- `MemoryExtractor`：从成功 Run 的快照提取结构化新增/更新建议。
- `RunCoordinator`：成功后的抽取调度、同用户任务串行化、任务异常与关闭管理。
- `agents/prompts/`：固定使用规则、选择提示词、抽取提示词，职责分别明确。

不改变现有工具执行、todo 续跑或子任务机制。测试和开发使用隔离数据目录，不操作正在运行服务的数据库、用户文件或配置。

## 验收条件

1. 用户明确表达一种长期偏好，成功轮次后产生 `feedback` 正文和索引；新 Thread 的相关请求能召回并注入它。
2. 三种类型均可保存和召回；`project` 类型被拒绝，临时任务进度不存入记忆。
3. 有索引时先选择、再主模型调用；空索引跳过；最多 5 条；工具循环不重复检索和累积注入。
4. 其他用户、非法 ID、目录穿越、符号链接均不能读取或更新。
5. 选择普通失败仍可正常回答；取消和总超时仍结束 Run；状态保存失败不会安排抽取。
6. 抽取失败不改变主 Run 的成功状态；并发轮次不丢失已提交记录；损坏索引能由正文修复。
7. 使用假模型、临时文件和临时数据库覆盖上述场景；运行相关测试和现有后端常规回归，不调用真实模型或 live 数据。
8. 数字编号返回能映射到本次的正确永久 ID；模型调用期间索引重排不会选错条目；越界编号和布尔值被拒绝。
9. 注入可控时间验证 `stable`：未满 48 小时为 `false`，满 48 小时为 `true`，实际内容更新后重置；读取和无变化的重复提取不重置。
10. 选择请求中的记忆候选只展示编号、`name`、`description`，不泄露正文、类型、文件名、来源、时间或 `stable`；选中后主请求收到正文和 feedback 的原因、适用方式，未选中的正文不注入。
