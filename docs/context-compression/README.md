# 上下文压缩使用说明

默认启用大结果落盘、Snip、空闲工具正文清理与 Auto-Compact。不存在 Context Collapse，也没有 90%/95% 两档折叠。

## 时序

每次请求先应用保存的 Snip/摘要记录，检查本上下文是否空闲超过 60 分钟，再计算新增内容提醒与请求容量。新增约 10K token 只提醒模型考虑 Snip；模型也可以在提醒前主动调用 `snip(message_ids=[...])`。一次提醒不意味着发生任何裁剪。

模型使用提供的消息 ID 选取无用旧消息；必须全组选中一条工具调用消息和对应结果。当前用户轮、系统约束、Task/子任务结果及其他不可重复工具结果受到保护。Snip 在保存记录后对下一次模型请求生效，删除区段显示边界标记，网页上的原聊天仍存在。

超过空闲间隔时，可恢复工具结果总体保留最近 5 个，当前完整用户轮额外保护。旧正文先确认保存在当前 Thread 的工具结果目录，模型得到清理标记与 `read_tool_result` 引用。清理正文不会重复执行 Bash、Edit 或 Write；文件/网页的当前状态也不等于其历史结果。

窗口默认按 1,000,000 token 计算，剩余约 33,000 token 时 Auto-Compact 单独调用模型，仅生成九段交接摘要；该调用没有可用工具，也不向用户输出回答片段。摘要与覆盖消息 ID 保存成功后进入后续上下文。原始历史、当前完整用户轮和不可裁剪结果保留。后续压缩继承现有摘要并整理新增活动历史。

## 配置

以下均为后端环境变量，修改线上配置和重启服务需单独部署授权。本模块开发未进行部署。

|变量|默认值|含义|
|---|---|---|
|DEER_MINI_CONTEXT_ENABLED|true|是否产生新的自动清理、提醒和摘要|
|DEER_MINI_CONTEXT_SNIP_ENABLED|true|是否向模型提供 Snip 工具和提醒|
|DEER_MINI_CONTEXT_CONTEXT_WINDOW|1000000|模型上下文容量，token|
|DEER_MINI_CONTEXT_COMPACT_REMAINING|33000|触发摘要的剩余 token 估计值|
|DEER_MINI_CONTEXT_REMINDER_TOKENS|10000|自上次提醒、Snip 或 Compact 后的新增 token 提醒间隔|
|DEER_MINI_CONTEXT_IDLE_SECONDS|3600|距离上一次本上下文聊天 API 尝试的空闲秒数|
|DEER_MINI_CONTEXT_KEEP_TOOL_RESULTS|5|空闲清理保留的最近候选结果数|
|DEER_MINI_CONTEXT_SUMMARY_TOKENS|8000|摘要输出 token 上限|

关闭策略仍保留并应用已经保存的压缩记录，避免上下文突然恢复膨胀。配置需满足摘要输出上限 < 压缩剩余阈值 < 窗口容量。

## 计量与失败边界

服务端返回的 prompt_tokens 用于校准本地估算；工具定义、参数、系统提示、消息、ID标记和模型要求回传的 reasoning 都计入请求估算。同模型已知的保守校准单独持久化，Snip、空闲清理、摘要和重启恢复后继续使用；切换模型时不套用其他模型的校准。当前没有供应商专用 tokenizer，因此剩余值和 10K 增量均为近似量，不保证恰好在真实服务端剩余 33,000 token 时触发。60 分钟同样是策略参数，不表示服务端缓存状态已被检测。

摘要不会自动确认新的问题，也不会将未验证事项写成已验证。失败、取消、无效摘要或保存失败不能报告压缩成功；当前任务和不可重复信息过大时明确报错，不静默丢弃。原始历史保留可供恢复与人工检查。

主/子 Agent 的压缩状态分别保存。旧快照缺少新字段时按未压缩历史读取，不需要直接修改旧消息或线上数据库。
