# 上下文压缩：需求与验收

确认依据：2026-10-07 本聊天。用户要求保留原始聊天，移除 Context Collapse，并明确 Snip 10K 增量提醒与 Auto-Compact 九段摘要、1M 窗口剩余约 33K 的触发线。此前 90%/95% 方案作废。

## 目标、范围与行为

服务持续对话的主 Agent 与独立子 Agent。复用大工具结果落盘；新增 Snip、空闲工具结果清理、Auto-Compact。无需修改成功 HTTP 响应；不改变长期记忆、文件 checkpoint、原生工具的业务语义，不部署或迁移线上数据。

1. Snip：功能开关控制工具和提醒。模型在普通 Agent 循环按稳定消息 ID 调用 snip；本地校验归属与完整工具交互组，保存裁剪记录，下次请求生效。不得用固定“前 N 轮”判断语义是否无用。系统信息、当前用户请求及其工具循环、不可重复结果不可 Snip。部分工具组目标拒绝，不扩大模型授权的 ID 范围。删除每个连续区段都产生边界标记；原始历史保留。
2. 每次请求准备都应用已有裁剪记录。约新增 10,000 token 时提醒模型考虑 Snip；提醒、Snip、Compact 后重新计数。提醒不自动调用 Snip、不保证裁剪，也不是调用工具的前提。提醒不写入原始消息；计数随快照恢复。
3. 当前上下文距最后一次聊天 API 尝试超过约 3,600 秒，在下一次请求准备时清理旧可恢复工具结果，候选总体保留最近 5 个，当前用户轮的工具结果额外保护。候选名称为 read_file/bash/grep/glob/web_search/edit_file/write_file，兼容用户列举的大小写名称；未知工具、task、write_todos、错误/中断结果保护。清理只替换模型请求中的正文为标记和引用；未落盘的原结果先确认保存。绝不为恢复历史而自动重放 Bash/Edit/Write。60 分钟是可配置启发式，不代表已检测到供应商缓存过期。
4. 不实现独立 Context Collapse。
5. Auto-Compact：窗口默认 1,000,000 token，估算剩余不大于 33,000 token 时触发；不使用 90%/95% 档。模型调用仅总结既有对话，tools=[]、非流式展示、禁执行任务。摘要保留目标、约束、纠正、关键决定、路径/函数/错误、已完成/已验证/未验证/待办与具体停留点；不新增确认问题，真实待答问题继续保留。
6. 摘要在 <summary> 中按九段输出：主要请求与意图；关键技术概念；涉及的文件与代码位置；遇到的错误及修复情况；已解决的问题与仍在排查的问题；用户消息清单；待办任务；当前工作；下一步。验证结构、无工具调用及大小，保存摘要和覆盖 ID 后才替代旧活动上下文。后续摘要继承之前摘要和新增活动消息，原始历史始终保留。
7. 当前完整用户轮、不可重复工具交互及系统约束保留；原始 reasoning 不变，保留的工具链继续满足模型回传协议。若受保护上下文自身过大或摘要后仍不能容纳，明确失败，不能丢掉保护内容或无界重复摘要。超长摘要输入分块生成承接摘要，块顺序不变，不能截断源文本冒充完整总结。
8. 主/子上下文各自持久化裁剪、摘要、计数与调用时间，子 Agent 使用独立 Snip 实例，不能裁剪父消息。保持用户/Thread/Run/工作目录校验。旧 Checkpoint 无新增字段时正常加载。
9. 每次实际 API 尝试前记录时间；服务端 usage 可用时采集 prompt_tokens，结合本地序列化请求估算校准。计算包含实际系统内容、工具定义/参数、消息、要求回传的 reasoning 与临时提示。没有供应商专用 tokenizer，指标是近似估算，阈值和窗口可配置；不声称精确剩余 token。
10. 复用模型错误中间件，SDK max_retries=0；摘要不执行工具、不发送主回答流片段。取消、关键持久化失败继续传递；提交期间等待在途保存完成，成功保存前不更新活动裁剪状态。原始 API/SSE 消息字段保持兼容，过程界面可展示整理上下文与 Snip。

## 配置决定

模块默认启用，提供总开关和独立 Snip 开关。窗口 1,000,000、剩余 33,000、提醒 10,000、空闲 3,600 秒、保留 5 个、摘要输出上限 8,000 token 均为受校验的配置。当前使用十进制 1M，可按供应商实际限制覆盖。关闭新增策略仍应用已经保存的摘要/裁剪记录，避免上下文恢复膨胀。主/子 Agent 均覆盖；不复制父 Snip 实例。

## 验收

- AC-1：普通模型循环调用 Snip；10K 以下可以主动调用；10K 仅提醒；提醒/Snip/Compact 三种重置及重启恢复正确。
- AC-2：合法 ID 裁剪下一次请求生效、每段边界正确、原始历史不变；未知/跨上下文/当前/不可重复/不完整工具组目标失败。
- AC-3：小于、等于、超过空闲线与最近 5 个边界正确；不可重复结果不变、原结果可读、无副作用重放，清理状态可恢复。
- AC-4：1M/33K 触发边界、配置校验、完整请求预算/usage、模型切换和新增消息统计正确；无 Context Collapse。
- AC-5：九段摘要、已有摘要承接、当前进度/用户要求输入、禁工具、结构与大小校验、分块输入、摘要不足以缩小时停止；提交成功后才生效。
- AC-6：取消、模型失败、流异常、持久化失败与重启都不伪报成功；真实工具不重放。摘要与主回答的重试/流状态隔离。
- AC-7：主 Agent、并发子 Agent、todos、memory、现有落盘与 checkpoint 的集成；旧快照/API 兼容、当前工具链及不可重复信息保护。
- AC-8：前端展示 Snip 与摘要状态，普通文本流/重试状态保持；针对性测试、后端常规回归、前端 typecheck/test/build 与独立审查完成。
